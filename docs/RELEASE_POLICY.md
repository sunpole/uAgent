# uAgent — единая политика версий и патчей

**Единственный источник текущей версии:** `version.json`. Остальные представления версии, включая `version.md`, README и страницу сайта, генерируются командой `npm run build`.

## Каждая новая поставка изменений

1. Отдельная ветка и Pull Request, без прямой работы в `main`.
2. Для нового набора изменений увеличивается версия SemVer (обычно PATCH: `0.2.0 → 0.2.1`). Для новой функциональности можно повысить MINOR, для несовместимости — MAJOR, с учётом допрелизной стадии.
3. Создаётся **один новый** файл `patches/<version>.json`: номер, дата, тип, заголовок, краткое описание, теги, детали и флаг `verified` — `true` лишь после реальной проверки.
4. Команда `npm run build` генерирует `docs/index.html` и `version.md`, обновляет README.
5. Команда `npm run check` проверяет структуру, сборку, версию и заготовки публикаций; CI дополнительно сравнивает номер версии с целевой веткой PR.
6. Перед объединением PR для новой версии обязательно подготовить публикацию uNews с реальным изображением и пройти контроль; каждый релиз должен быть представлен в Telegram, а исторические 0.1.0–0.2.1 объединяются в первый intro-пост. Если нет изображения или проверки — PR заблокирован.
7. Для Telegram используется **только** штатная очередь `sunpole/uNews` и реальный медиафайл. Актуальная политика: [UNEWS_POLICY.md](UNEWS_POLICY.md).

Самый короткий способ создать запись:
```powershell
npm run patch:new -- --title "Краткое описание" --type feature --tags "агент,код" --summary "Что действительно изменилось"
```
Команда увеличивает номер текущей версии на один PATCH, создаёт JSON-запись и обновляет генерируемые материалы. Откройте PR только после проверок.

## Где находятся сведения
- `version.json` — единственная текущая версия;
- `version.md` — генерируемая человекочитаемая версия;
- `patches/*.json` — **история** версий (предыдущие значения не являются конкурирующими текущими версиями);
- `docs/index.html` — генерируемая главная страница с архивом патчей;
- `docs/PROGRESS.md` — подтверждённые результаты испытаний;
- `news/YYYY-MM-DD-*.md` — только готовые к проверке публикации в Telegram, не дубль всего архива.

## Правила uNews
- До первой публикации требуется `type: intro`, `series: uagent`, `project: uAgent`.
- Реальные подтверждённые изображения, без AI-generated имитаций: `image_origin: real`.
- Секреты, токены, изображения с личными данными и ручные Telegram footers запрещены.
- `news/` с датированным MD — **очередь публикации**, а не черновики. Черновики хранятся в `patches/`.
- Местная проверка `check:unews` — предварительная; **источник истины** и публикация находятся в `sunpole/uNews` (политика и GitHub Actions). Не запускать Telegram API из uAgent.
- Не публиковать о функциях, которые ещё не работают.

## Ограничения автоматизации
CI проверяет Pull Request. Чтобы запретить **все** прямые коммиты без увеличения версии, настройка branch protection / ruleset в GitHub должна сделать проверки обязательными. Пока это не подтверждено, политика существует как автоматическая проверка, а не физически непреодолимый запрет.
