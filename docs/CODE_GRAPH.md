# Карта кода: дерево + граф связей

## Зачем
При каждом запросе агенту не нужно целиком копировать весь репозиторий в контекст. Он может начать с краткой структурной карты, выбрать подходящие файлы, затем прочитать **актуальный** код перед изменениями.

## Этап 1 — уже подготовлен
`npm run graph` строит файловый граф с узлами (файлы) и связями (локальные `import`, `require` и относительные ссылки Markdown). Выход: `docs/repo-graph.json` и `docs/REPO_MAP.md`.
Это **файловая карта зависимостей**, а не полноценный граф функций и классов. Не использовать её как достоверный анализ всех вызовов или runtime-зависимостей.

## Этап 2 — нужен для полноценной Repo Map
- Tree-sitter: AST-дерево и извлечение классов, методов, функций, определений и ссылок.
- Типизированные связи и языковая семантика; по возможности SCIP/LSP для точного поиска определений.
- Инкрементальная индексация по хешам изменённых файлов с удалением устаревших рёбер.
- Граф важности (например, PageRank) и ограничение контекста по бюджету токенов.
- Для каждой связи — источник, файл, строка и уровень уверенности.
- Проверки изменений через тесты, а не доверие карте.

Не добавлять лишнюю графовую базу данных на раннем этапе. Для небольшого репозитория хватит JSON-графа. Данные индекса не должны содержать ключей, содержимого `.env`, приватных репозиториев или секретов.

## Источники
- [Aider Repository Map](https://aider.chat/docs/repomap.html) — Tree-sitter, файлы, символы, PageRank, бюджет токенов.
- [SCIP — Design](https://github.com/sourcegraph/scip/blob/main/docs/DESIGN.md) — индекс навигации по определениям и ссылкам.
