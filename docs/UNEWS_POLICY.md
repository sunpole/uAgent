# uAgent → uNews: обязательная публикационная политика

## Источники истины
Перед подготовкой каждой публикации читать актуальные [AGENTS.md uNews](https://github.com/sunpole/uNews/blob/main/AGENTS.md), [README uNews](https://github.com/sunpole/uNews/blob/main/README.md), [UNEWS.md](https://github.com/sunpole/uNews/blob/main/UNEWS.md), [скрипт публикационной политики](https://github.com/sunpole/uNews/blob/main/scripts/patchnote-policy.js) и [контроль изображений](https://github.com/sunpole/uNews/blob/main/docs/IMAGE_INTEGRITY.md), а также AGENTS.md и docs/RELEASE_POLICY.md uAgent. При расхождении правил публикации приоритет имеет актуальный uNews.

## Обязательный порядок для каждой версии
1. Повысить единую версию в `version.json`, создать `patches/VERSION.json` и выполнить `npm run build` / `npm run graph`.
2. Записать факты, проверки и ограничения в `docs/PROGRESS.md`; не выдавать планы за реализованные функции.
3. Подготовить один `news/YYYY-MM-DD-uagent-*.md` с версией из `version.json`, а рядом с ним **настоящий** PNG/JPEG/WebP результата. Каждый новый релиз сопровождается новостью; для старых версий 0.1.0–0.2.1 допускается общий первый intro. Датированная запись = очередь, не черновик.
4. Первая публикация любой новой серии обязана быть `type: intro`. Для этого проекта `project: uAgent`, `series: uagent`, `repo_url: https://github.com/sunpole/uAgent`, `web_url: https://sunpole.github.io/uAgent/`.
5. `queued_at` должен соответствовать реальному моменту постановки в очередь и быть точным UTC `YYYY-MM-DDTHH:mm:ssZ`. `image_origin: real` обязателен.
6. Основной визуал — реальный снимок действующего сайта/программы, фото или фактический экспорт результата. Запрещены AI-generated обложки, вымышленные экраны, placeholder, личные данные, секреты или токены. Снимок можно делать автоматизированно обычным браузером; он остаётся подлинным.
7. Текст по-русски, кратко и фактологично. Не вставлять вручную `Ссылка:`, `О проекте:` или финальные хештеги: uNews самостоятельно дополняет footer.
8. Перед слиянием PR выполнить `npm run check` и фактическую проверку политики/изображений uNews на подготовленном патчноуте. `check:unews` в uAgent — лишь предварительная проверка.
9. Реальную отправку выполняет **только GitHub Actions в sunpole/uNews**. Не копировать секреты и не отправлять через локальный Bot API. После публикации проверить `data/published.json` и `data/project-intros.json`, сохранить URL и не создавать дубликат.
10. Если изображения, CI или проверки нет, **не объединять PR и не считать пост опубликованным**. Блокер записать в PR/Issue. Исправление уже опубликованного сообщения выполнять через официальный repair workflow uNews.

## Факты для первого intro — подтверждены пользователем
- Ollama **0.40.16**, модель **qwen2.5-coder:3b**: успешная загрузка и работа локально.
- Скорость в двух тестах: **8,04** и **8,03 токена/с**, не универсальный бенчмарк.
- Диалог на русском языке, код функции `is_prime`, три примера; ответ закончился по лимиту `num_predict=240`.
- `ollama ps`: **2,5 ГБ**, **75% CPU / 25% GPU**, контекст **4096**, раннер `llamacpp`.
- **uAgent ещё не автономный агент**: память, инструменты и мобильный интерфейс не реализованы.

## Статус считается завершённым
Не после создания MD, не после CI и не после слияния PR, а **после фактического сообщения в @uNewsLog** с зафиксированным идентификатором в состоянии uNews.
